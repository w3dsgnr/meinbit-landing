# Payroll section — scroll animation spec

## Что это
Интерактивная секция про функцию кошелька **payroll**, заанимированная по скроллу.
Живёт в разрыве белой подложки между секциями `wallet` и `crypto`.

## Сущности (ВАЖНО — не путать)
Это два разных уровня:
- **Транзакция** — единичный перевод на один адрес.
- **Payroll (строка в интерфейсе)** — один запуск, в котором пользователь разом перевёл на много адресов. То есть payroll = **стак из множества транзакций**, отправленных одной операцией. В списке интерфейса одна строка = один payroll, а не одна транзакция.

Смысл анимации: показать, что **много транзакций сворачиваются в один payroll**, и таких payroll'ов в списке может быть **много**.

## Решение по контенту телефона (ответ на твой вопрос)
**Вариант 1 — Rebuild in HTML/CSS.**
Причина: карточки-транзакции должны влетать в мокап и **сворачиваться в живые строки payroll** — значит список это живой DOM, а не запечённый PNG. Используй существующие токены проекта и Tabler-иконки. Длинный повторяющийся список payroll'ов (~2200px) генерь из данных, не верстай руками каждую строку. Данные — моковые, из Figma.
Шрифты: **Nunito** (основной/акцентный текст) + **Inter** (вторичный), как в дизайне карточки-транзакции `5:507`.

## Раскадровка по скроллу (это ядро задачи)
Секция пинится на время всей анимации, всё гонит один GSAP timeline со `scrub`.

1. **Заголовок.** На входе в секцию — крупный `Payroll transactions` по центру.
2. **Уход заголовка.** По скроллу заголовок тускнеет (`opacity`) и блюрится (`filter: blur`), уезжает на задний план.
3. **Появление мокапа.** Поверх заголовка въезжает стандартный мокап телефона по центру (как в предыдущих секциях проекта). По краям от телефона — маленькие плавающие карточки-транзакции.
4. **Транзакции → один payroll.** Пачка краевых карточек-транзакций заезжает в мокап и **схлопывается в ОДНУ строку-payroll** (стак переводов, отправленных за один раз). Сумма строки при этом набегает счётчиком как сумма карточек — это и показывает механику «много транзакций → один payroll». Реализуй через **GSAP Flip**: записать состояние карточек → их позиции сводятся в слот одной строки → `Flip.from()` со stagger → crossfade в готовую строку-payroll с тоталом и статусом `Paid`. Карточка ≠ строка 1:1.
5. **Много payroll'ов + внутренний скролл.** Схлопывание (Flip) показываем РОВНО один раз — для первой строки-героя; остальные строки появляются по `opacity` при скролле (lazy-reveal), без повторного Flip. Список заполняется и скроллится внутри телефона на всю длину (~2200px), **не выходя за края** (`overflow: clip` по рамке). Внешний скролл страницы запинен; внутренний скролл = прогресс того же ScrollTrigger, маппится на `translateY` контента.

## Тех-ограничения
- Анимировать только `transform` / `opacity` (+ `filter` для блюра заголовка). `will-change` на анимируемых.
- React-чистка: `useGSAP` / `gsap.context().revert()`.
- `prefers-reduced-motion`: показывать финальное состояние (телефон со списком) сразу, без проигрывания.
- Мобайл (<768px): упрощённая ветка через `gsap.matchMedia()` — без пина и scrub; телефон и список появляются лёгким fade/въездом, без внутреннего скролл-джекинга.
- GSAP и плагины (ScrollTrigger, Flip) — бесплатные, ставить из npm.

## Вне скоупа (сейчас НЕ делаем)
- Видео-фон, скругления краёв секции, сам разрыв белой подложки — реализуй статикой, без анимации. Это отдельная задача.
- Реальные серверные данные — список на моках.

## Definition of done
По скроллу через секцию: заголовок гаснет и блюрится → въезжает телефон с краевыми карточками-транзакциями → пачка карточек влетает и **схлопывается в одну строку-payroll** (сумма набегает счётчиком) → дальше много payroll-строк набегают каскадом и скроллятся внутри рамки, не вылезая за края → на выходе из секции пин снимается чисто, без скачка.
**Проверка в реальном браузере (Playwright MCP):** сними кадры на `timeline.progress()` = 0 / 0.33 / 0.66 / 1 и сверь каждый с соответствующим битом раскадровки.
